# Implementation Plan: Legacy Time report filter reflow and label association (R01/X01)

**Branch**: `fix/report-filter-reflow` | **Date**: 2026-10-22 | **Base**: `8ae8458e` | **Spec**: [spec.md](spec.md)

## Summary

The plan has four parts:

- **Labels.** Attach every visible filter label on the legacy Time report to its
  native control through the existing `FormGroup` id contract.
- **Width caps.** Stop filter groups and controls from widening the page with
  `min-w-0 max-w-full`.
- **Narrow layout.** Below 640px, the filter panel drops its padding, border and
  fill (`p-0 border-0 bg-base`), and the dates use `px-1`. Each class is paired
  with an `sm:` variant that restores the current panel and date padding, border
  and fill at 640px and wider. Control height is the separate, approved exception
  below.
  The coordinator measured this direction in native Chrome
  ([research.md, D1](research.md#d1-date-layout-at-320px-with-200-text)).
- **Generator.** Four of those `sm:` variants are not generated today, so
  `crates/horae/build.rs` adds four existing base utilities to its `RESPONSIVE`
  list: `p-6`, `px-3`, `border` and `bg-secondary`
  ([research.md, D2](research.md#d2-make-the-responsive-candidate-real)).
- **Control height.** The filter inputs and selects opt into one new base utility,
  `min-h-control`, which maps to the existing `--height-form-control` token. Selects
  grow from 42px to 44px; this is the one recorded desktop exception
  ([research.md](research.md#control-height)).

There are no `horae.css` rules, tokens or shared component changes.

## Design notes

- `FilterSelect` gains `id: String`. Its existing `.form-group` div takes
  `min-w-0 max-w-full`, its label takes `for`, and its select takes the id.
  Group by is handled the same way inline.
- From, To and Project tag use `FormGroup` with its `id`. `FormGroup` has no class
  prop, so each sits in a wrapper `div` with `min-w-0 max-w-full`, and shared
  defaults stay unchanged. Flex items keep child margins inside them, so the
  wrapper does not change the vertical rhythm.
- The controls also take `min-w-0 max-w-full`: the dates through `Input`'s
  `class`, and the selects directly. This matches the measured candidate.
- Order of operations: the browser suite is drafted first (red on the base for
  labels and the 320/390 32px dates). Then markup, the generator entries, and the
  runner append.

## Gates

1. In the slot: build (regenerating `horae-utils.css`), clippy, the wasm check,
   `nix fmt`, the focused browser suites, the shared style audit, and the
   cross-screen suites.
1. Native Chrome: the full 24-case matrix (16 cases plus the short windows), keyboard and
   calendar editing, and desktop pixel identity except the approved select height
   exception (42px to 44px). Done by the coordinator.
1. Scoped impeccable `audit`/`adapt` review of the result (no init).
1. Two independent reviews and full CI on the exact head. No commit, push or PR
   until the coordinator collects the work.
