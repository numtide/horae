# Implementation plan: editor reflow

## Context and constraints

Reuse feature 011 US6/US7, its data model, server contracts and quickstart.
The visual reference is `design/project/app/13_New Project.dc.html`, `DESIGN.md`
and `../contracts/new-project.md`. This correction changes no fields, actions,
permissions, money calculations, schema or dependencies.

Use the existing Rust/Dioxus form, Modal and generated utility framework.
Preserve all handlers, draft/edit guards and conditional branches. Prefer local
wrapping and shrink constraints; never hide overflow, remove controls, truncate
action labels or shrink text to conceal a defect. Existing name truncation is
intentional and remains unchanged.

## Measured causes and implementation

At 390px with 200% root text, native Chrome measured an editor scroll width of
543px against 380px available. The seeded legacy form had no selected date;
the classic scrollbar occupied 10px. A separate headless regression with a
selected date measured 556/390 and a discard dialog at 454/324. These are
different states, not conflicting measurements.

The rem-sized preferred controls grew with text while their field cells did not.
The corrected layout keeps normal preferred widths and allows reflow:

- **Dates and code:** wrapping date controls, capped button/input widths and
  `min-width: 0` on `.np-dates > .form-group`. The latter is structural because
  the shared FormGroup has no caller class. The calendar itself is unchanged.
- **Assignments:** wrapping task/person rate and budget groups, the Billable
  All/None shortcuts and person identity. At viewport widths up to 480px,
  overrides use the full assignment row. Names retain their title/truncation;
  role text must not collapse to zero width. Add everyone can wrap its icon.
- **Billing and taxes:** shrinkable Currency, Billable rates and Project fee
  fieldsets; wrapping amount groups and fee-mode items; capped second-tax group.
  Fieldset defaults previously imposed min-content widths on the whole section.
- **Milestones:** an inline-size container uses the existing stacked layout
  below 30rem. The viewport-only breakpoint missed enlarged desktop text.
- **Dialogs:** discard, reload, New client and task-access callers use wrapping
  actions and existing `px-3 sm:px-6` utilities. Horizontal padding changes only
  below 640px; vertical/desktop padding and shared Modal defaults stay unchanged.
- **Spacing:** `.np-page` owns `--project-panel-gutter: min(var(--space-5), 6.25vw)`. The new opt-in `px-project-panel` utility is
  generated by `build.rs` and used only by editor Tasks, Team and Billing.
  Assignment column gaps are capped at that gutter. At 100% text from 320px up,
  panel padding remains 20px and gaps 16px. The form gutter is similarly capped
  only below 480px. No shared token or utility default changes.
- **Persistent actions:** retain the fixed editor shell and pinned footer.
  The footer has a 25% maximum height and uses its existing vertical scrolling,
  leaving at least 75% of the editor for fields. A 50% diagnostic cap left too
  little room for enlarged radio cards; a document-scrolling alternative was
  rejected because it contradicted the persistent-actions contract.

At 100% text, the intended changes are full-width narrow-screen overrides and
a scrollable footer only when its actions exceed a quarter of the editor.
At 390x568 the normal 105px footer fits; at 390x320 it remains pinned but must
scroll. Existing short-screen/navigation checks remain mandatory. These changes
are not permission to alter unrelated screens.

## Validation and delivery

1. Run `new-project-keyboard` and `project-edit` with isolated PostgreSQL fixtures.
   Keep all old cases: empty dates at 100%, configured/legacy persistence,
   permission guards, conflicts, retries, discard/reload recovery and no writes
   on Cancel. Add selected dates at 200%, all billing/budget branches,
   320/390/768/1440px, short portrait/landscape and all four dialogs.
1. Measure the inner form, field cells, row controls and modal content boxes,
   not merely the document. Check button-content clipping, calendar/Today fit,
   role-text width and actual forward/reverse Tab navigation. Focused controls
   must fit their own scrollport above the footer. Accumulate geometry failures
   to diagnose the full matrix, then assert an empty list; never suppress them.
1. Verify the actual build in native Chrome at the specified widths in both
   themes. Capture normal/enlarged form and modal states. Disclose physical
   devices/engines not tested; text enlargement is not browser zoom.
1. Run the complete browser regression, tests, native/WASM checks, strict lint,
   SQLx cache verification and formatting. The full browser check covers shared
   style regressions even though the new utility is opt-in.
1. Resolve independent technical and visual/UX reviews on the final artifact.
   Publish one bounded PR and merge only with mandatory exact-head CI green.

## Constitution and dependencies

All five principles remain satisfied: exact arithmetic, domain purity, datastore
and mutation paths are unchanged; reproducible Nix gates remain mandatory.
No exception or new contract is required. Use only disposable local databases,
never real Harvest mutations or persistent-database migrations.

The branch starts at editor-return `cfa85271`; rebase after that increment merges
and repeat affected checks. Limit work to two implementation increments and one
heavy build at a time; the coordinator owns browser/DB/build resources.

Spec Kit's setup, prerequisite, tasks and analysis procedures reuse the parent
package and this bounded spec/plan/tasks. There are no extension hooks or
installed agent-context update script; do not claim absent commands ran.
