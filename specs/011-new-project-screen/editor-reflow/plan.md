# Implementation plan: editor reflow

## Context and constraints

Reuse feature 011 US6/US7, its data model, server contracts and quickstart.
The visual reference is `design/project/app/13_New Project.dc.html`, `DESIGN.md`
and `../contracts/new-project.md`. This correction changes no fields, actions,
permissions, money calculations, schema or dependencies.

Use the existing Rust/Dioxus form, Modal and generated utility framework.
Preserve all handlers, draft/edit guards and conditional branches. Prefer local
wrapping and shrink constraints; never hide overflow, remove controls, truncate
action labels or shrink text to conceal a defect. Existing name truncation is
intentional and remains unchanged.

## Measured causes and implementation

At 390px with 200% root text, native Chrome measured an editor scroll width of
543px against 380px available. The seeded legacy form had no selected date;
the classic scrollbar occupied 10px. A separate headless regression with a
selected date measured 556/390 and a discard dialog at 454/324. These are
different states, not conflicting measurements.

The rem-sized preferred controls grew with text while their field cells did not.
The corrected layout keeps normal preferred widths and allows reflow:

- **Dates and code:** wrapping date controls, capped button/input widths and
  `min-width: 0` on `.np-dates > .form-group`. The latter is structural because
  the shared FormGroup has no caller class. The calendar itself is unchanged.
- **Assignments:** wrapping task/person rate and budget groups, the Billable
  All/None shortcuts and person identity. At viewport widths up to 480px,
  overrides use the full assignment row. Above 1180px the identity column has a
  `--space-24` floor and the controls `minmax(0, auto)`, so controls wrap instead
  of taking the identity's width. The identity text (`flex-1` with the opt-in
  generated `basis-project-identity` utility, `flex-basis: var(--space-24)`)
  prefers 6rem beside the avatar. At normal text long names therefore truncate beside it;
  with less room they wrap below it. Only role text may break inside a word
  (`wrap-anywhere`). Names keep their title and truncation; role text must not
  collapse to zero width. Add everyone can wrap its icon.
- **Billing and taxes:** shrinkable Currency, Billable rates and Project fee
  fieldsets; wrapping amount groups and fee-mode items; capped second-tax group.
  Fieldset defaults previously imposed min-content widths on the whole section.
- **Milestones and project types:** inline-size containers (`np-milestones`,
  `np-types`) apply below 30rem. Milestones use the existing stacked layout, and
  each type card spans the full row. The viewport-only breakpoints missed
  enlarged text just above 1180px and on desktop.
- **Dialogs:** discard, reload, New client and task-access callers use wrapping
  actions and existing `px-3 sm:px-6` utilities. Horizontal padding changes only
  below 640px; vertical/desktop padding and shared Modal defaults stay unchanged.
- **Spacing:** `.np-page` owns `--project-panel-gutter: min(var(--space-5), 6.25vw)`. The new opt-in `px-project-panel` utility is
  generated by `build.rs` and used only by editor Tasks, Team, Billing and the
  three footer actions (20px at 100% text, as `.btn` already was).
  Assignment column gaps are capped at that gutter. At 100% text from 320px up,
  panel padding remains 20px and gaps 16px. The form gutter is similarly capped
  only below 480px. No shared token or utility default changes.
- **Persistent actions:** retain the fixed editor shell and pinned footer.
  The footer is normally capped at 25% of the editor, keeps its 16px vertical
  padding and scrolls vertically beyond that. `.np-page` is a size container
  (`np-editor`; its height is definite through `h-full`). Compaction depends on
  the editor's own height, not the viewport: below 19rem, which is
  4 × (control height + 2rem padding), a 25% cap would be shorter than one normal
  row of actions. There the footer uses `--space-1` vertical padding and a cap of
  `max(25%, control height + 2 × --space-1 + 1px border)`, so Save stays whole at
  rest. That floor can exceed a quarter, so the fields keep the remainder rather
  than a guaranteed 75%. Because the threshold is in rem, enlarged text reaches it
  sooner, and an ordinary short laptop window at 100% text keeps the 16px padding.
  A 50% diagnostic cap left too little room for enlarged radio cards. A
  document-scrolling alternative was rejected because it contradicted the
  persistent-actions contract.

At 100% text, the intended changes are full-width overrides on screens up to
480px, long names that truncate beside the avatar, a footer that scrolls only
beyond its cap, and footer compaction only in a short editor. Not every layout is
identical to before: above 1180px, the identity floor can make controls wrap
onto more lines, or put the identity text under the avatar, so names stay usable.
Existing short-screen and navigation checks remain mandatory. These changes are
not permission to alter unrelated screens.

Known limits:

- The editor's size container and both container queries assume `.np-page` keeps
  a definite height through `h-full` from the fixed shell. A future shell where
  the editor's height depends on its content would collapse under size
  containment. The existing short-screen and open-navigation checks would catch
  that, but the assumption is not otherwise enforced.
- On short editors the pinned footer can hold fewer rows than its actions need.
  Cancel, Discard draft and the status text then scroll within the footer.
  Focusing them scrolls them into view, and Save is checked whole at rest, but
  not every action is visible at once.
- Names retain intentional truncation and their full accessible labels/title;
  this does not make the full name visible on touch screens. Role words may
  break internally at 320px with 200% text.
- Native milestone date/amount fields scroll or clip their internal text at
  320–390px with 200% text. Width checks establish that controls fit, not that
  every value is simultaneously visible. The second-tax removal control keeps
  the specific accessible name `Remove second tax` when it wraps.
- The unchanged shared calendar fits and its Today action is reachable at
  320px/200%, but day numbers and headings overlap. The shared sidebar also has
  enlarged-text overflow. These remain open cross-screen acceptance work, not
  fixes or accessibility claims delivered by this editor increment.
- Creation's existing header says `Saving draft…` during finalization; the short
  footer label does not correct that status wording. No save handler changes.
